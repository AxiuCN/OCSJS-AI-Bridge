# 协议与适配

## OCS 题库协议（权威：OCSJS 原版源码）

OCSJS 通过**题库配置**（AnswererWrapper JSON：`url` / `method` / `headers` / `data` / `handler`）请求外部服务。

- 请求只使用三个标准字段：`title` / `options` / `type`
- 期望返回：`res.code === 1 ? [res.question, res.answer] : [res.message, undefined]`
- `handler` 是字符串，经 `Function()` 构造后执行，必须返回该数组形状
- OCSJS 5.x 起 `contentType` 废弃，改用 `responseType`

`ocs-answerer-wrapper.json.example` 是与原版契约一致的模板，OCS 端零改动即可接入。

## 三种上游协议

| kind | 请求 | 图片 | 结构化输出 | 推理开关 |
|---|---|---|---|---|
| `ollama` | `POST {base_url}/api/chat` | `message.images`（纯 base64） | `format: "json"` | `think`（布尔） |
| `openai_chat` | `POST {base_url}/v1/chat/completions` | content 里的 `image_url` | `response_format` | 无等价物，忽略 |
| `openai_responses` | `POST {base_url}/v1/responses` | `input_image` | `text.format` | `reasoning.effort` |

**Ollama 不实现 Responses API**，这是需要适配器层的原因。适配器只做协议翻译，答案语义（字母映射、判断归一、分隔符拼接）一律由领域层处理。

## 图片机制

### OCSJS 5.x 直传（推荐）

OCSJS 5.x 新增 `env.images` / `suggestion_title` / `suggestion_options`：浏览器自己把题干与选项里的图片下载并转成 PNG data URL 后随请求提交。

题库配置用**字段解析器**提交数组：

```json
"data": {
  "title": "${title}",
  "options": "${options}",
  "type": "${type}",
  "images": { "handler": "return (env) => env.images" }
}
```

不能写成 `"images": "${images}"`——占位符替换是字符串替换，数组会被逗号拼接并破坏 data URL。

服务端在收到的 data URL 数量与自身解析出的图片数量一致时，按出现顺序绑定「题干/材料图片 N」「选项 X 图片 N」标签；数量不一致时退回原逻辑，不强行配对。

### 服务端下载（兼容原版）

原版 OCS 不传图片数组，图片 URL 混在题干/选项文本里，由服务端下载。受登录态保护的地址可能失败，此时要么安装浏览器侧取图补丁，要么升级到 5.x 直传。

## 容错解析

模型输出先整体 JSON 解析，失败再剥离 Markdown 围栏、抠取第一个 JSON 对象。缺 `answer` 或空内容一律报错，**不猜答案**。空正文（Ollama 偶发）会关闭 thinking 重试一次，仍失败则明确报错。

## 能力声明

后端能力（`vision` / `thinking`）以配置为准，**不按模型名推断**。例如同一 Ollama 实例上 `qwen3.5:9b` 有 vision，`deepseek-r1:14b`、`qwen3-coder:30b` 没有。
