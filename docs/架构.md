# 架构

## 目录

```
src/
  server.ts        入口：配置 → 服务 → 优雅关闭
  config.ts        JSONC 解析、${ENV} 展开、启动校验、敏感值擦除
  jsonc.ts         JSONC 解析（剥注释、尾随逗号、BOM）
  env.ts           .env 读取与 ${VAR} 展开
  types.ts         配置与领域类型
  httpapi.ts       /v1/answer、/health、鉴权、限额、错误分流
  routing.ts       候选链、超时预算、能力过滤、降级
  policy.ts        策略钩子（运行时决定候选链）
  semaphore.ts     每后端并发闸
  backends.ts      按 kind 实例化后端
  normalize.ts     题型/选项归一、图片标记、[BLANK_n]
  images.ts        data URL 校验、下载、MIME 嗅探、并发
  format.ts        答案 → OCS 可回填字符串
  prompt.ts        与协议无关的请求模型
  domain.ts        领域类型
  upstream/        三种协议适配器 + 容错解析
  logger.ts        结构化 JSON 日志
  redact.ts        白名单脱敏投影
  shutdown.ts      优雅关闭
tests/             单元与契约测试
scripts/           doctor 与四类真实链路实测
deploy/            systemd 单元、Windows 启动脚本、部署指南
docs/              本目录（除 private/ 入库）
```

## 分层

| 层 | 职责 | 不负责 |
|---|---|---|
| 接入层 `httpapi` | 鉴权、限额、错误分流 | 不解析题目 |
| 领域层 `normalize` / `images` / `format` | 题型归一、图片准备、答案回填 | 不感知上游协议 |
| 提示层 `prompt` | 构造与协议无关的请求模型 | 不决定协议格式 |
| 路由层 `routing` / `policy` | 候选链、预算、能力过滤、降级 | 不构造协议请求 |
| 上游层 `upstream` | 协议翻译、响应文本提取 | 不解析答案语义 |

**关键边界**：领域层只实现一次，三种适配器共用——换后端不改变 OCS 回填行为。

## 请求数据流

```
POST /v1/answer
  → 鉴权 → 读体 → normalizeQuestion（题型/选项/图片标记/挖空）
  → ImagePreparer（有 data URL 直接用，否则按 URL 下载）
  → policy.decide(ctx) 或 routes 默认候选链
  → 逐候选：能力过滤 → 预算检查 → 适配器请求 → 容错解析 → formatOcsAnswer
  → { code: 1, answer, ... } 或 { code: 0, message }
```

## 配置三层

1. `config.jsonc`：结构、后端、路由、策略（可用 `${ENV}` 占位）
2. `.env`：凭据与地址（不入库）
3. `docs/private/`：本机部署信息（不入库，新克隆上不存在）
